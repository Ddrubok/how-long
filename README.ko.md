# how-long

[English](README.md) · v0.3.0 · [MIT 라이선스](LICENSE)

`how-long`은 AI가 작업을 시작하기 전에 예상 소요 시간을 알려주도록 하는 스킬입니다. 작업 수행뿐 아니라 필요한 확인과 결과 전달까지 고려합니다. 시간을 알려준 다음에는 요청받은 작업을 진행하고, 예상 시간만 물었다면 답변으로 끝냅니다.

스킬은 AI가 따라 읽는 지침입니다. 이 스킬은 제목과 목록을 표현할 수 있는 텍스트 형식인 Markdown으로 작성했습니다. 별도의 프로그램이나 백그라운드 서비스는 필요하지 않습니다.

## 사용하기

이 저장소에서 **Code → Download ZIP**을 선택하고 압축을 풉니다. 아래 예시를 그대로 쓰려면 압축을 푼 폴더 이름을 `how-long`으로 바꿔 주세요.

AI가 PC의 파일을 읽을 수 있다면 다음과 같이 요청합니다. 파일 경로는 실제 위치에 맞게 바꿉니다.

> how-long/SKILL.md를 읽고 예상 소요 시간을 먼저 알려준 다음, 제출 버튼의 문구를 “저장”에서 “보내기”로 바꾸고 결과를 확인해 주세요.

AI가 파일을 읽을 수 없다면 [SKILL.md](SKILL.md)의 내용을 대화에 붙여 넣고 작업을 요청합니다. AI가 지침을 전달받아야 적용할 수 있습니다.

스킬을 지원하는 앱에서는 앱이 안내하는 스킬 폴더에 넣어 사용해도 됩니다. 설치 위치와 호출 방법은 앱마다 다릅니다. `$스킬이름`으로 호출하는 앱에서는 다음과 같이 사용할 수 있습니다.

```text
$how-long 예상 소요 시간을 먼저 알려준 다음 제출 버튼을 수정해 주세요.
```

매 작업에 적용하려면 앱에서 지원하는 사용자 또는 프로젝트 지침에 다음 문장을 추가합니다. 경로는 실제 위치에 맞춥니다.

> 모든 작업을 시작하기 전에 how-long/SKILL.md를 읽고 적용하세요.

폴더를 다운로드하는 것만으로 모든 작업에 자동 적용되지는 않습니다.

## 표시되는 내용

AI는 사용자의 언어로 짧게 예상 시간을 알려줍니다. 아래 대괄호는 각 작업에 맞는 값으로 바뀝니다.

> ### 🟦 예상 소요 시간: 약 [시간]
>
> 예상 범위 [하한]~[상한]. [시간이 달라질 수 있는 주된 이유]

단순한 작업은 첫 줄만으로 충분할 수 있습니다. 오류 원인이 불분명하거나 실행 환경을 준비해야 한다면 예상 범위와 짧은 설명을 덧붙입니다.

## 시간을 예상하는 방법

1. **어디까지 해야 끝나는지 정합니다.** 요청을 완료하는 데 필요한 확인·저장·결과 전달을 포함합니다. 시간 안내 이후부터 완료까지를 예상합니다.
2. **계획을 바꿀 수 있는 부분을 확인합니다.** 필요하면 관련 파일이나 기존 오류 메시지를 읽습니다. 이미 있는 기능이라면 새로 만드는 대신 조금만 수정해도 될 수 있습니다.
3. **실제로 할 일을 나눕니다.** 원인 조사, 수정, 도구 실행, 대기, 검증에 걸릴 시간을 고려합니다. 코드 수정이 작더라도 필요한 빌드에는 시간이 걸립니다.
4. **추가 작업이 생길 가능성을 살펴봅니다.** 순조롭게 끝나는 경우, 가장 그럴듯한 경우, 확인된 위험 때문에 더 걸리는 경우를 비교합니다. 근거가 있을 때 수정과 테스트 재실행을 포함합니다.
5. **적절히 반올림해 알립니다.** 가장 그럴듯한 시간을 말하고, 불확실성이 크면 범위를 덧붙입니다. 근거가 부족한데도 초 단위까지 정확한 것처럼 표현하지 않습니다.

버튼 문구를 바꾸는 일과 가끔 작동하지 않는 버튼을 고치는 일은 둘 다 파일 하나를 수정할 수 있습니다. 하지만 두 번째 작업에는 원인 조사도 필요합니다. 실제로 할 일을 따로 계산하면 이런 차이를 반영할 수 있습니다. 순서대로 하는 작업은 시간을 더하고, 실제로 동시에 진행할 수 있는 작업은 마지막 작업이 끝날 때까지의 시간과 결과를 합치는 시간을 고려합니다.

## 예상 시간을 얼마나 믿어도 될까요?

AI는 현재 가진 정보로 시간을 예측합니다. 타이머를 돌리거나 시간 이력을 저장하지 않으며, 이전 예측의 오차를 학습하지도 않습니다. AI의 응답 속도, 도구의 대기 시간, 예상하지 못한 오류에 따라 실제 시간은 달라질 수 있습니다.

예상 범위는 작업이 진행될 수 있는 상황을 고려한 값입니다. 실제로 측정한 오차 범위나 완료 시간을 보장하는 약속은 아닙니다. 이 버전에서 예측 오차가 얼마나 줄었는지는 실측으로 확인하지 않았습니다.

승인을 기다리는 것처럼 끝나는 시점을 알 수 없는 대기는 따로 표시합니다. 나머지 작업의 예상 시간에는 그 대기가 포함되지 않습니다. 예상 시간을 알리기 전에 진행한 최소한의 사전 확인 시간도 제외됩니다.

## 글자 크기와 색상

기본적으로 제목 서식과 파란색 사각형 하나를 사용해 시간 안내를 찾기 쉽게 표시합니다. 글자는 앱의 밝은 테마나 어두운 테마를 따릅니다. 서식 지원이 적은 앱에서는 굵은 글씨나 일반 텍스트로 표시할 수 있습니다.

실제 크기와 색상은 앱에 따라 달라집니다. 글자 서식을 직접 지정할 수 있다면 본문보다 약 1.25배 큰 굵은 글씨와 파란색 `#2F78C4`를 권장합니다. 선택적 아이콘과 UI 설정은 지원 앱에서 스킬을 표시하기 위한 정보이며, 채팅 본문의 글자색을 바꾸지는 않습니다. 자세한 표시 규칙은 [SKILL.md](SKILL.md)에 있습니다.
