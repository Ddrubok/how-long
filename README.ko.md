# how-long

[English](README.md) · v0.4.0 · [MIT 라이선스](LICENSE)

`how-long`은 AI가 작업을 시작하기 전에 예상 소요 시간을 한 번 알려주도록 하는 스킬입니다. 필요한 지침을 읽은 뒤 주어진 맥락이 충분하면 바로 보고합니다. 이어서 이미 허용된 작업을 진행하며, 예상 시간만 물었다면 보고 후 끝냅니다.

스킬은 AI가 따라 읽는 지침입니다. 이 스킬은 제목과 목록을 표현할 수 있는 텍스트 형식인 Markdown으로 작성했습니다. 별도의 프로그램이나 백그라운드 서비스는 필요하지 않습니다.

## 사용하기

이 저장소에서 **Code → Download ZIP**을 선택하고 압축을 풉니다. 아래 예시를 그대로 쓰려면 압축을 푼 폴더 이름을 `how-long`으로 바꿔 주세요.

AI가 PC의 파일을 읽을 수 있다면 다음과 같이 요청합니다. 파일 경로는 실제 위치에 맞게 바꿉니다.

> how-long/SKILL.md를 읽고 예상 소요 시간을 먼저 알려준 다음, 제출 버튼의 문구를 “저장”에서 “보내기”로 바꾸고 결과를 확인해 주세요.

AI가 파일을 읽을 수 없다면 [SKILL.md](SKILL.md)의 내용을 대화에 붙여 넣고 작업을 요청합니다. AI가 지침을 전달받아야 적용할 수 있습니다.

스킬을 지원하는 앱에서는 앱이 안내하는 스킬 폴더에 넣어 사용해도 됩니다. 설치 위치와 호출 방법은 앱마다 다릅니다. `$스킬이름`으로 호출하는 앱에서는 다음과 같이 사용할 수 있습니다.

```text
$how-long 예상 소요 시간을 먼저 알려준 다음 제출 버튼을 수정해 주세요.
```

매 작업에 적용하려면 앱에서 지원하는 사용자 또는 프로젝트 지침에 다음 문장을 추가합니다. 경로는 실제 위치에 맞춥니다.

> 모든 작업을 시작하기 전에 how-long/SKILL.md를 읽고 적용하세요.

폴더를 다운로드하는 것만으로 모든 작업에 자동 적용되지는 않습니다.

## 시간을 예상하는 방법

예상 시간은 보고 시점부터 최종 결과 전달까지의 실제 경과 시간입니다. 필요한 검증·저장·일반적인 도구 대기를 포함하며, 보고 전에 진행한 사전 확인 시간은 제외합니다. 예측할 수 없는 사용자 응답·승인·외부 서비스 대기는 따로 표시합니다. 작업 범위가 무한정 열려 있으면 추정 가능한 부분만 예상합니다.

맥락이 충분하면 추가 도구 조회 없이 보고합니다. 예상치를 크게 바꿀 미확인 요소가 있을 때만 작은 읽기 전용 확인을 최대 두 개, 한 번의 병렬 호출 묶음으로 수행합니다. 병렬 호출이 불가능하면 한 개로 제한합니다. 이 상한은 예상 시간 산출을 위한 추가 조사에만 적용하며, 필요한 지침을 읽거나 보고 후 작업을 수행하는 데 적용하지 않습니다. 보고 전에는 파일 수정·빌드·테스트 실행·설치·본격적인 조사를 하지 않습니다.

가장 가능성 높은 실행 경로를 기준으로 AI의 추론과 작성, 순차적인 도구 호출과 대기, 필요한 검증과 재작업을 고려합니다. 모든 작업에서 세 가지 시나리오를 만들지는 않습니다. 확인 후에도 남은 중요한 불확실성은 짧은 가정이나 범위로 표현합니다.

기존 실행 시간은 명령과 환경 조건이 비슷할 때만 참고합니다. 캐시를 재사용하는 실행과 초기 실행은 다를 수 있으며, timeout은 기다릴 수 있는 상한이지 예상 실행 시간이 아닙니다. 순차 작업은 시간을 더합니다. 실제 병렬 작업은 앞선 결과를 기다려야 하는 단계들을 연결했을 때 가장 오래 걸리는 경로를 기준으로 하고, 작업 조정과 결과 통합 시간도 포함합니다.

사람의 개발 시간, 고정된 파일당 시간, 임의의 처리 속도·재시도 확률·일괄적인 여유 비율을 사용하지 않습니다. 모든 AI 작업이 몇 초나 몇 분 이내에 끝난다고 제한하지도 않습니다.

## 표시되는 내용

사용자의 언어로 기본 한 줄, 필요하면 최대 두 줄의 내용을 보고합니다. 적절히 반올림한 대표 예상치 하나를 먼저 말합니다. 중요한 불확실성이 있을 때만 범위와 주요 원인을 덧붙이며, 대표 예상치는 범위 안에 있어야 합니다. 단계별 시간 설명은 요청받았을 때만 제공합니다.

Markdown 제목이 지원되고 허용될 때는 다음처럼 표시할 수 있습니다. 대괄호는 작업에 맞는 값으로 바뀝니다.

> ### 🟦 예상 소요 시간: 약 [시간]
>
> 예상 범위 [하한]~[상한]. [시간이 달라질 수 있는 주된 이유]

그 외에는 평문을 사용합니다.

```text
예상 소요 시간: 약 [시간]
```

사용자가 명시한 출력 형식을 우선합니다. 보고 후에는 이미 허용된 작업만 진행하며 기존 승인 조건을 유지합니다.

## 한계

예상 범위는 가능한 결과의 범위입니다. 통계적으로 계산한 신뢰구간이나 보장된 최대 시간이 아닙니다. 근거가 바뀌었을 때 조정하며, 마감에 맞추거나 불확실성을 감추기 위해 임의로 줄이거나 늘리지 않습니다. 이 규칙이 주기적인 갱신을 뜻하지는 않습니다.

타이머·시간 기록 저장·과거 오차 자동 학습·카운트다운·완료 후 실측 시간 보고 기능은 없습니다. AI의 응답 속도, 도구 대기, 예상하지 못한 오류에 따라 실제 시간은 달라질 수 있습니다. 보고가 얼마나 빨라졌는지, 예측 오차가 얼마나 줄었는지는 성능 측정으로 확인하지 않았습니다.
