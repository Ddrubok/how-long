# how-long

[English](README.md) · v0.5.0 · [MIT 라이선스](LICENSE)

`how-long`은 AI가 작업 전에 예상 소요 시간을 한 번 알려주도록 하는 스킬입니다. 주어진 맥락을 바탕으로 추정하고 중요한 불확실성을 밝힌 뒤, 이미 허용된 작업을 진행합니다. 예상 시간만 물었다면 보고 후 끝냅니다.

스킬은 Markdown으로 작성한 지침 파일입니다. 별도의 프로그램이나 백그라운드 서비스는 필요하지 않습니다.

## 사용하기

저장소에서 **Code → Download ZIP**으로 내려받아 압축을 풉니다. 아래 경로를 그대로 쓰려면 폴더 이름을 `how-long`으로 바꿉니다.

AI가 PC의 파일을 읽을 수 있다면 실제 경로에 맞춰 요청합니다.

> how-long/SKILL.md를 읽고 예상 시간을 먼저 알려준 다음, 버튼 문구를 “저장”에서 “보내기”로 바꾸고 결과를 확인해 주세요.

파일을 읽을 수 없다면 [SKILL.md](SKILL.md)의 내용을 대화에 붙여 넣고 요청합니다. 스킬을 지원하는 앱에서는 앱이 안내하는 스킬 폴더에 넣어도 됩니다. `$스킬이름` 호출을 지원한다면 다음처럼 사용합니다.

```text
$how-long 예상 시간을 먼저 알려준 다음 제출 버튼을 수정해 주세요.
```

매 작업에 적용하려면 앱에서 지원하는 사용자 또는 프로젝트 지침에 다음 문장을 추가합니다. 경로는 실제 위치에 맞춥니다.

> 모든 작업을 시작하기 전에 how-long/SKILL.md를 읽고 적용하세요.

다운로드만으로 자동 활성화되지는 않습니다. 설치와 호출 방법은 앱마다 다릅니다.

## 시간을 예상하는 방법

필요한 지침을 읽은 뒤 맥락이 충분하면 즉시 보고합니다. 예상치를 크게 바꿀 미확인 요소가 있을 때만 작은 읽기 전용 확인을 최대 두 개, 한 번의 병렬 호출 묶음으로 수행합니다. 병렬 호출이 불가능하면 한 개로 제한합니다. 이 상한은 추정을 위한 추가 조사에만 적용하며, 필요한 지침 읽기나 보고 후 작업에는 적용하지 않습니다. 단순히 숫자를 더 정밀하게 만들려는 조회는 생략합니다. 보고 전에 수정·빌드·테스트·설치·본격적인 조사는 하지 않습니다.

예상하는 대상은 보고 시점부터 최종 결과 전달까지 걸릴 시간입니다. 추론, 작성, 도구 호출과 대기, 필요한 검증·저장·재작업을 포함합니다. 보고 전 사전 확인은 제외합니다. 예측할 수 없는 사용자 응답·승인·외부 대기는 따로 표시하며, 추정 가능한 부분만 예상하고 제외한 항목을 밝힙니다.

가장 가능성 높은 실행 경로를 사용하고 시나리오 구성을 강제하지 않습니다. 순차 작업은 시간을 더합니다. 실제 병렬 작업은 앞선 결과를 기다려야 하는 단계들을 연결했을 때 가장 오래 걸리는 경로를 기준으로 하고, 조정과 결과 통합 시간도 포함합니다. 관측된 실행 시간은 명령과 조건이 비슷할 때만 참고합니다. 캐시 실행과 초기 실행은 다를 수 있고, timeout은 예상 실행 시간이 아닙니다. 처리 속도·재시도 확률·파일당 시간·일괄 여유 비율을 지어내거나, 사람의 개발 시간을 그대로 쓰거나, 모든 AI 작업을 몇 초나 몇 분 이내로 제한하지 않습니다.

## 근거와 불확실성

v0.5.0에서는 다음 세 가지를 명시합니다.

- 비교할 수 있는 실행 시간 근거가 없으면 작업 내용을 바탕으로 한 대략적인 추정이라고 표시합니다. 범위가 명확한 작업은 시간 이력이 없어도 추정할 수 있습니다.
- 측정값·로그·과거 기록·검증·완료를 주장하려면 근거가 있어야 합니다. 사용자가 알려준 시간을 AI가 직접 측정한 값처럼 말하지 않습니다.
- 의미 있는 예상치나 범위를 정할 수 없다면 그 사실과 부족한 조건 하나를 밝힙니다. 출력 형식을 채우려고 숫자를 만들지 않습니다.

예를 들어 수정할 버튼 문구가 주어지면 작업 범위가 명확하므로 대략적인 시간을 예상할 수 있습니다. 하지만 “이 프로젝트의 테스트는 평균 1분 걸립니다”라고 말하려면 실제 근거가 필요합니다. 작업 내용을 아는 것만으로 그 평균을 알 수는 없습니다.

## 표시되는 내용

사용자의 언어로 한 줄, 필요하면 최대 두 줄의 내용을 보고합니다. 추정할 근거가 있으면 반올림한 대표 예상치부터 말합니다. 중요한 불확실성이 있을 때만 범위와 주요 원인을 덧붙이며, 대표 예상치는 범위 안에 둡니다. 단계별 설명은 요청받았을 때만 제공합니다.

아래는 비교할 실행 시간 근거가 없는 경우의 출력 예시입니다. 대괄호는 작업에 맞게 바뀌며, 두 번째 줄은 필요할 때만 붙습니다.

> ### 🟦 예상 소요 시간: 약 [시간] (작업 내용 기반 추정)
>
> 예상 범위 [하한]~[상한]. [주요 불확실성]

이 제목 서식은 Markdown 제목이 지원되고 허용될 때만 사용합니다. 그 외에는 평문으로 표시하고, 사용자가 지정한 형식을 존중합니다. 의미 있는 추정이 어렵다면 다음처럼 보고할 수 있습니다.

> 현재 정보로 소요 시간을 추정하기 어렵습니다. 이전할 데이터의 범위가 정해지지 않았습니다.

예상 범위는 가능한 결과의 범위이며 통계적 신뢰구간이나 보장된 최대 시간이 아닙니다. 근거가 바뀔 때만 조정하며, 마감에 맞추거나 불확실성을 감추기 위해 바꾸지 않습니다. 주기적인 갱신 기능을 추가한 것은 아닙니다.

## 한계와 파일

예상 시간에 맞추려고 필요한 검증을 생략하거나 완료했다고 주장해서는 안 됩니다. 기존 승인 조건을 지키며 일반적인 작업 소통은 계속합니다.

타이머·시간 이력 저장·과거 오차 자동 학습·카운트다운·주기적인 ETA 갱신·완료 후 실측 시간 보고 기능은 없습니다. 행동 검증이나 성능 측정으로 보고 지연, 예측 오차, 근거 없는 주장이 줄었다는 것을 입증하지는 않았습니다.

실행 지침은 [SKILL.md](SKILL.md)에 있습니다. `agents/`와 `assets/`는 선택적 스킬 표시 정보와 아이콘이며, 메시지 서식을 제어하지 않습니다. 지침을 텍스트로 전달할 때는 필요하지 않습니다.
